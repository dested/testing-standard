## What / Why

Sal builds with agents and no longer reads most code. Measured in November 2026: no repo had a git hook, no deploy ran a test, and 33 of 66 planted one-line bugs passed every check. `gate` runs a repo's checks on a clean copy of a commit, with its own databases, and writes a signed receipt. In block mode, `gate guard push` (which the agents' own `agent-guard` PreToolUse hook calls before letting a `git push` through) denies an agent's push to a protected branch without one. **gate never installs a git hook, never writes git config, never creates or pushes refs** (Sal, 2026-11-20: "i dont like global git hook. you are the only thing writing code anymore on this computer. its just for you. dont mess with git."). Sal's own pushes aren't checked.

**Report mode everywhere (Sal, 2026-11-20):** "dont do frozen ropes. i dont want anything gates for now. you can oupsh but dont ever faila  deploy ." The gate informs; nothing is gated. Every repo runs `"mode": "report"`, sal-starter and its forks included. The block machinery below stays built and tested (gate.json v1 still accepts `block`), but gate's output and skill never present it as a goal: `gate status` states facts instead of readiness, `gate init --mode block` prints the decision first, and agents never flip or propose a flip, or run `gate allow-weaken`, unless Sal raises it.

The standard gate implements is public at https://github.com/dested/testing-standard (`README.md` the standard, `adopt.md` how to bring a repo on, `examples.md` real cases).

The contract both builders worked to is [`contract.md`](contract.md) (frozen 2026-11-20); this doc is how gate implements it. The five guarantees: **clean copy** (checks run on `git archive <commit>`, never the working tree), **own databases and ports**, **skipped counts as failed**, **a receipt** (block mode denies an agent's push without one), **two modes** (`report` records and never blocks; `block` refuses).

## Behavior spec

**Commands.** `gate [run]` (HEAD), `--sha <rev>`, `--dirty`, `--only a,b`, `--all`, `--json`, `--verbose`, `--quiet`, `--no-wait`, `--trigger manual|push|probe`; `gate status [--json]`; `gate init [--mode report|block] [--force]`; `gate guard push --cwd <dir> [--json] -- <git push args>`; `gate allow-weaken --sha <rev> --why "<Sal's words>"`; `gate probe [--sha] [--from <file>] [--since <rev>] [--max <n>] [--seed <n>] [--only-files <glob>] [--json] [--verbose]`; `gate probe report [--json]`; `gate tests [--all | --failed] [--check <name>] [--file <glob or text>] [--grep <text>] [--json] [--html [--no-open]]`; `gate where [--json]`; `gate doctor [--json]`; `--help`, `--version`. `gate live` is reserved (exit 2, "isn't built yet").

**Exit codes.** 0 every check passed · 1 a check (or `setup`) failed: the commit is red · 2 usage or gate.json error (outside a repo, no gate.json at the commit, unknown key, bad version) · 3 gate couldn't run (no Postgres, no disk, lock held with `--no-wait`, interrupted). `gate guard push` is its own scale: 0 allow · 1 deny · 2 couldn't parse (agent-guard allows on 2 and shows the note, so a gate bug never blocks a push). `gate probe`: 0 at or above `probe.minRate` with no missed critical bug, 1 otherwise (or a red baseline), 2/3 as for run, 130 interrupted. `gate doctor` 0 / 3. `gate tests`: 0 when it printed (a red last run included: it reports, gate judges), 2 no gate.json at HEAD or a bad flag (`--check` naming no check, `--all` with `--failed`), 3 couldn't read gate's own files.

**gate.json.** zod, `.strict()` at every level, so a typo is exit 2 naming the key. `gate init` writes report mode; `--mode block` first prints `Sal's standing decision is report mode everywhere (2026-11-20); only use block if he asked in this conversation`, then does it (exit unchanged). Fields and defaults as in the contract. One addition: a check may not be named `setup` (gate's own line).

**The run, in order.**
1. Resolve the commit and read `gate.json` from it (`--dirty`: from the working tree). Validate `--only` names.
2. Take `<work root>/lock` (`{pid, run, at}`, `wx`). A live holder: wait and say so on stderr, or exit 3 with `--no-wait`. A dead pid is stale and taken over.
3. Plan databases: each entry's server comes from that var in the caller's env, else the first `copy.env` file that sets it; none → exit 3 naming the var and every file read. Run database `gate_<slug>_<run>_<n>`.
4. Sweep: drop `gate_<slug>_<8 chars>_…` databases of other runs older than 6 hours.
5. Clean copy: `git archive <sha> | tar -x` into `tree.new-<run>/`, rename the `copy.keep` directories over from the old `tree/` (depth ≤ 4, not nested in another kept one, only where the parent still exists), delete the old tree, rename. `--dirty` then overlays `git diff --name-only HEAD` + untracked non-ignored files and removes deleted ones. Then the `copy.env` files are copied from the working tree.
6. Ports: one per `ports[]` name, free on 127.0.0.1 and ::1 (a box without IPv6 counts as free there).
7. **setup** (one line): create each database (from its template on a cache hit), run `setup` commands, run `migrate` for misses, save templates, then terminate every connection to the run databases so a harness can use them as a `TEMPLATE`. Any failure is a failed `setup` check (exit 1); a Postgres failure is exit 3.
8. Checks in order: `sh -c` in its own process group at the copy root (or `cwd`), output to `runs/<run>/<check>.log`. Stop at the first failure unless `--all`; the rest print ` --   <name>    not run`. A timeout SIGTERMs the group, SIGKILLs it 2s later; every check's group is SIGKILLed when it exits, so a server or `sleep` it started dies with it.
9. Receipt (only when every check ran and passed, not `--dirty`, not `--only`), history line (every run), cleanup.

**Environment of every command.** The contract's allowlist (`PATH`, `HOME`, … `WSL_INTEROP`) plus `pass[]`, then `GATE=1`, `GATE_RUN`, `GATE_SHA`, `GATE_ROOT`, `GATE_CHECK` (`setup` / `migrate` / the check name), `NO_COLOR=1`, `FORCE_COLOR=0`, each database URL and port. gate never loads the copied `.env`; process env wins over `.env` in Bun's autoload and in `node --env-file` (proven by test 5, which connects with `Bun.SQL` and reads the URL in Node).

**Databases.** Every drop goes through `dropGateDatabase`, every create/terminate through `assertGateName`: the name must match `^gate_[a-z0-9_]+$` (≤ 63). Cleanup drops every database starting `gate_<slug>_<run>_` with `DROP DATABASE … WITH (FORCE)` on pass, fail, gate error and SIGINT/SIGTERM/SIGHUP (a second signal exits at once; the sweep catches what's left after 6 hours). Template cache: with `key`, sha256 over the migrate command and every file under the key paths → `gate_tpl_<slug>_<n>_<hash12>`; a hit is `CREATE DATABASE … TEMPLATE`, a miss migrates and then saves a template and drops that entry's older ones. A template that can't be saved is logged in `setup.log` and the run goes on.

**Run ids** are 6 base36 chars of unix seconds + 2 random: the sweep reads a database's age from its name instead of asking Postgres (decisions.md 2026-11-20).

**Counts.** `lib/gate/counts.ts` recognizes `bun test`'s summary (` N pass|fail|skip|todo`, closed by `Ran N tests across`), `(fail) <name>` lines, `error: 0 test files matching`, and Playwright's list/line summaries (`  N passed|failed|flaky|skipped|did not run|interrupted`, names indented under failed/flaky, `Error: No tests found.`). Several `bun test` runs in one check are summed; any one reporting zero tests fails it. Patterns come from real output in `test/gate/fixtures` (bun 1.4.3, @playwright/test 1.65.1): regenerate with `scripts/gate-fixtures.sh`, never from memory. With `skips: "fail"` (default) skipped, todo, did-not-run or zero tests fail the check on exit 0; flaky passes and is listed on the output and in the receipt as `<check>: <test>`.

**Output.** Header `gate  <repo>  <sha7>  <mode>  clean copy · N databases`, then one line per check as it finishes (`pass|FAIL| -- `, name, time, counts or reason). A failure adds the failing test names (≤ 20), the last 40 log lines and `log <path>`, then `FAILED at <check>. Fix it, commit, run gate again.` Pass: `receipt <sha7> (tree <tree7>) written · git push is allowed` / `receipt written · report mode never blocks a push` / `passed · no receipt (<why>)`. Uncommitted files on a HEAD run: one `note:` line. Every printed line is scrubbed: database passwords and every value (≥ 6 chars) from the copied env files become `***`; URLs print as `postgres://user:***@host:port/db`. Logs on disk are raw. `--json`: one object on stdout (the history line + `receipt`, `logs`, `failures`, `flaky`, `exit`, and `error` on exit 2/3). `--quiet`: nothing on a pass, the whole report on a failure. `--verbose`: each output line as it arrives (stderr under `--json`).

**Receipts and history.** `<git common dir>/gate/receipts/<tree sha>.json`, keyed by tree so an amend of the message or a content-neutral rebase keeps it. `sig` = HMAC-SHA256 over the canonical JSON (keys sorted at every level) of every other field, keyed by `~/.destedtui/gate/key` (32 random bytes, 0600, made on first use). Bad signature, wrong tree or no key → treated as absent. History: `<git common dir>/gate/history.jsonl`, one line per run; an interrupted or broken run adds a pseudo-check `gate` with the reason.

**Work root.** `$GATE_WORK/<slug>`, else `/w/junk/<repo>/.gate` for `/w/code/<repo>`, else `<tmp>/gate/<slug>`. Holds `tree/`, `runs/<run>/` (newest 20 kept), `lock`, and `push.log` (output of report-mode background runs).

**The push guard.** `gate guard push --cwd <repo> -- <args after "git push">`. Read-only: only read-only git (`rev-parse`, `show`, `for-each-ref`, `show-ref`, `symbolic-ref`, `config --get`, `remote`). What would be pushed where comes from the arguments (`planPush` in `lib/gate/guard.ts`):
- Options: every `git push` option is known (`-u`, `-f`, `--force-with-lease[=…]`, `-o <v>`, `--repo`, `--tags`, …; bundled short flags); anything else → exit 2.
- Remote: first positional (or `--repo`), else `branch.<cur>.pushRemote`, `remote.pushDefault`, `branch.<cur>.remote`, else `origin`.
- No refspec → the current branch to `@{push}` when set, else the same name (detached HEAD → exit 2). `--all`/`--branches`/`--mirror` → every local branch. `src`, `src:dst`, `+src:dst`, `HEAD`/`@` (→ current branch name), `refs/heads/x`, single-`*` patterns on both sides. Deletes (`:dst`, `--delete`/`-d`), tags (`refs/tags/x` or a name that's only a tag), `--tags` alone and non-branch `refs/…` destinations are skipped. An unresolvable source → exit 2.
- Per (commit, branch): remote-tracking `refs/remotes/<remote>/<branch>` already at the commit → allow. **Weakening**: the tracking ref's gate.json says `block`, lists this branch, and the pushed gate.json is gone, invalid, `report`, drops a check, allows skips on a check, or stops listing the branch → deny, unless `<git common dir>/gate/allow.jsonl` has an allowance for that exact sha (`gate allow-weaken`, which appends `{at, sha, why}`). No gate.json at the pushed commit → allow. Branch not in `branches` → allow. Block: a valid receipt for the commit's tree allows with one line, otherwise deny with the short sha, why (no receipt / last run failed at `<check>`) and `next: cd <repo> && gate` (`--sha <short>` when it isn't HEAD). Report: allow with one line of facts (`gate: report mode · <sha7>: <no receipt… | last run failed at <check>> · push allowed`, or `<sha7> passed · push allowed`); with neither receipt nor any full run for the tree, start `gate run --sha <sha> --trigger push --quiet` detached (once per tree: a marker in `<work root>/push-runs/<tree>`, 6 h; output appended to `<work root>/push.log`).
- A pushed URL or path instead of a named remote has no tracking refs: no weakening check, and a protected branch needs a receipt.
- `--json`: `{decision: allow|deny|error, remote, lines, targets: [{branch, sha, allow, reason}], skipped, next?}`.

agent-guard (`~/.claude/sal/hooks/agent-guard.ts`, in sals-powershell-setup) does the calling; the lead wires it. `gate doctor` reports `agent guard: not wired yet` until that file mentions `gate guard` (informational, never a failure).

**The probe.** A green gate only means something if its checks can fail. `gate probe` plants one bug at a time in the clean copy and reports every one that still passed every check.
- **Same machinery as `gate run`** (`session.ts`): lock for the whole probe, clean copy, `setup`, template cache. Then the set-up databases are snapshotted as `gate_<slug>_<run>_base<n>`, and every bug gets fresh copies of them (`resetDatabases`: drop `<db>` and `<db>_*`, `CREATE DATABASE … TEMPLATE base`).
- **Baseline:** every check once, unmodified; red → exit 1 `the commit is red at <check>; a probe needs a green commit`, nothing planted, no result file (a history line is written).
- **Per bug:** write the one line, reset databases, run the checks in order with timeout `min(own, 3 × baseline + 30 s)`, the first failing check **caught** it (a timeout counts: `caught … (timeout)`), none → **missed**. The original bytes go back in a `finally` and their sha256 is verified before the next bug; a mismatch is exit 3. A check killed by a signal is never counted as a catch.
- **Which bugs** (`probe/select.ts`): files at the commit matching `probe.include`, minus `probe.exclude` (glob, exact path or directory), test files (`*.test.*`, `*.spec.*`, under `e2e`/`test`/`tests`/`__tests__`), generated/vendored dirs (`node_modules`, `dist`, `build`, `generated`, `.gate`, `*.gen.*`, `.d.ts`), non-TS/JS files, and lines with `// probe-ignore: <why>` on them or the line above. No `probe.include` → exit 2. `--since <rev>`: only lines added or changed by `git diff -U0 <rev> <sha>`. `--only-files <glob>` narrows further. `--max` (30) samples round-robin across operators and, within each, across areas (the directory just below the candidates' common prefix), one bug per line, seeded (`--seed`, default the first 8 hex of the tree sha; mulberry32).
- **`--from <file>`:** a `.jsonl` (the audit prototype's shape: `file`, `line`, `op`, `before`, `after`, trimmed and cut at 200) or a stored probe result `.json`. The line: the given number if its trimmed text starts with `before`, else the one line that does; then the operator's variant whose trimmed, cut text equals `after`. When the operator can't give the recorded change any more (unknown operator, not mutable, a different variant) but a line still reads exactly `before` (both texts uncut, under 200 characters), the recorded edit is applied as written, with the line's own indent, and marked `replayed as recorded` on its output line and as `note` in the result file. Otherwise (line gone, several lines match) → `stale`; an excluded path or probe-ignore line → `excluded` with the reason; neither is counted. Both audit files replay: every recorded change regenerates through the ported operators; at sal-starter's HEAD on 2026-11-20, 37 of 40 resolve and 3 are stale (the code moved); jim-app 26 of 26.
- **Operators** (`probe/operators.ts`, one table, ported from the prototype): drop-guard, drop-call, flip-eq, flip-logic, flip-bool, flip-rel, drop-not, off-by-one, flip-arith. Comments, imports, `type`/`interface`/`declare` lines and type blocks are skipped; matches inside a string are skipped; off-by-one and flip-arith skip any line with a quote.
- **Exit:** 0 when catch rate (caught / (caught + missed)) ≥ `probe.minRate` (0.9) and no missed bug is under a `probe.critical` glob; else 1, and the last line says which (`FAILED: catch rate 80% is below minRate 90%`, `missed under critical: <file:line>`, `nothing counted`). SIGINT/SIGTERM: the line is restored, databases dropped, what finished is written, exit 130.
- **Output:** header after the baseline (`gate probe  <repo>  <sha7>  <n> bugs  baseline <check> <time> · …`), one line per bug (`caught  <check>  <file:line>  <op>  [(timeout)] <first failing test>`, `MISSED  <file:line>  <op>  <before> → <after>`, `exclud`/`stale ` with the reason), then `N counted · N caught (per check) · N missed · N excluded · N stale`, `catch rate N%`, `results <path>`.
- **Results:** `<git common dir>/gate/probes/<ISO time>-<sha7>.json` (every bug with outcome, check, all failing tests with the file the runner named, ms; the baseline; the summary; `commitAt`; seed or `from`). One `trigger: "probe"` history line (ignored by receipts, the guard's "last run failed" and status's receipt line). `--json` prints the result plus `path`.
- **`gate probe report`:** catch rate per probe; per check, bugs caught first across all probes, and checks that never caught one; test files at HEAD (same test patterns) that never appear in a stored failing test (runner paths match a repo file by suffix), with `a file can be idle because no bug landed near it`.
- **The headline probe is the newest sampled one** (source `sample` or `since`, `isReplay`/`headline` in `probe/store.ts`): a `--from` replay of a list you've already fixed goes to 100% and says little (the testing standard). `gate status`, `gate tests` and the `--html` page all quote it, and name the replays stored after it as not counted; with only replays stored, each says `no sampled probe yet` and how many replays it ignored.
- **`gate status`** shows the newest sampled probe (date, rate, missed, exit, `newest sampled · N --from replays since, not counted`) and, in report mode, one line of facts: `sampled probe 100% · nothing missed · every check passing` when HEAD has a passing receipt and the newest sampled probe exited 0 on a commit at most 14 days old, else `open: <why; why>` (no passing receipt, no probe yet, no sampled probe yet (only --from replays), the newest sampled probe failed and why, it is of an old commit). In the runs list a replay's run is flagged `replay` instead of `probe`. `--json`: `probe` is the newest sampled probe, plus `probeReplaysSince` and `replayRuns`; the `ready: {ready, why}` field is kept.
- **`gate probe report`** lists every probe; a replay's row ends `replay of <list file>` (`--json`: `replay`, `from`).

**`gate tests`.** Every test the repo has and its last result; runs nothing, writes nothing (`lib/gate/tests.ts`, parser `lib/gate/testlog.ts`).
- **Sources:** history.jsonl lines whose `runs/<run>/` folder is still kept (newest 20, newest first, any trigger); each check's `<check>.log`, or a probe's `baseline-<check>.log` (planted-bug logs `b<n>-*.log` are never read). The receipt for HEAD's tree, and the stored probes. Works on every run gate ever kept: nothing new is recorded at run time.
- **Per test** (`parseTests`, sharing counts.ts's summary patterns): bun's `path:` header and `(pass|fail|skip|todo) name [1.2ms]` lines, the error lines bun prints above a `(fail)` (from the first `error:` line, source context and stack skipped, ≤ 4), the `› <workspace> <script>` line a monorepo test script prints before each workspace, and the end-of-run `N tests failed:` recap skipped. Playwright's list reporter: one `✓|✘|-` line per attempt (`[project] › file:line:col › title (time)`, `(retry #n)`), so ✘ then ✓ is flaky and a `-` is did-not-run when the summary has did-not-run and no skipped; the numbered failure blocks give the error. Fixtures: `test/gate/fixtures/tests-*.txt`, real gate logs of a monorepo. bun prints no `(pass)` lines when `CLAUDECODE=1` is set; gate's allowlisted env drops it, so gate's logs have them (a log that names fewer tests than its summary says so).
- **Paths:** a printed path resolves to a file at HEAD through the workspace's folder (package.json `name` → its directory), else an exact path, else a unique suffix; unresolved names print as the runner wrote them.
- **Per check:** the newest kept run that ran it. A check the newest run didn't reach (gate stops at the first failure) shows its tests from the older run with `from the run of <time> (<sha7>): the newest run didn't reach it`. Counts per status from the log, time from history.
- **Per test:** status, time, and history across the kept runs that named it (`failed in 2 of the last 14 runs`, `flaky in …`, and in JSON `lastFailure` with run, log and error). Clean = passed now and never failed or flaked in a kept run.
- **Probe:** the newest sampled probe's date, commit, catch rate and missed, then `· newest sampled · N --from replays since, not counted` (`--json`: `probe`, `probeReplaysSince`); per test file, the planted bugs whose failing tests named it, across every stored probe (by suffix, as `gate probe report`), `caught none` plus the same idle caveat.
- **Not run yet:** files at HEAD named `*.rule.test.ts(x)`, `*.api.test.ts` or `*.flow.spec.ts` (outside node_modules) that no kept run named.
- **Output:** header (`gate tests  <repo>  <sha7>`, `last run …`, `probe …`), one line per check, then per check one line per test file (mark, test count, path, catch count) with every non-clean test under it (error lines, `log <path>`); Playwright checks get one row per flow with a column per project (width). `--all` names every test, `--failed` only non-clean ones, `--grep` lists matches by name, `--check`/`--file` narrow (a glob matches from the root or any folder; plain text is a substring). Layout fits the terminal's width (else `COLUMNS`, else 100): long names end in `…`, a note that doesn't fit wraps instead of cutting a name. Colour only on a TTY without `NO_COLOR`. `--json`: the whole `TestsReport`, narrowed by the same flags, never truncated.

**`gate tests --html`** (`lib/gate/page.ts` gathers, `lib/gate/html.ts` renders, pure). The same report (narrowed by the same flags) plus probe coverage, each test's detail and code, as one page: inline CSS, JS and data, no server, no CDN, one light theme; screenshots are files beside it, linked relative to it. Written to `<work root>/tests.html` (`W:\junk\<repo>\.gate\tests.html`), its Windows path printed (`--json`: `{path, win, opened, openError?}`), and opened with `winopen` (else `explorer.exe`; `GATE_OPEN` overrides, which the tests use) unless `--no-open`. Exit as `gate tests`. Answer first, depth opt-in (Sal, 2026-11-22: "make it better. and clean this page up"):
- **Top:** the repo, then one line: `✓ All green on <sha7>` / `✘ Red on <sha7>: failed at <check>` from the newest non-probe run, plus `HEAD <sha7> is N commits past it` when it is. Then test results, failing, flaky (when any), the **newest sampled probe**'s catch rate against `minRate` (a sample or `--since`, never a `--from` replay; its date, commit and the replays not counted in the tooltip; `—` and why with only replays) and what it missed. A sticky bar (static under 700 px) with the section links and a filter box.
- **Problems** (only when any): every test that isn't a clean pass (check, title, which widths, its first error line or history note; a click opens it), a check that failed without a test, a check whose results are from an older run, every planted change whose newest planting passed every check (count, how many under `probe.critical`, the files, each linking to its bugs), coverage maps with gaps or that aren't maps, test files no kept run named.
- **Checks:** state, tests, counts, time, the run and commit the results are from, its log.
- **Flows** (a Playwright check): one expander per area, the feature part of the standard's title (`<feature>/<flow> · <what a person sees>`, also after a describe chain; anything else is `other`), its summary passes per width (`desktop 9/9 · phone 9/9`) and time; open when anything in it isn't clean. Inside, one row per flow with a column per width (Playwright project). `Expand all` button.
- **Bun checks:** one expander per check (open when red), one per test file inside (open when anything in it isn't clean).
- **A test's drawer** (a click on any row; `#t<n>` in the URL, so Back closes it; Esc and the scrim too): title, `file:line`, check, the run's time and commit, its log. A card per width: status, time, attempts, a square per kept run (oldest to newest; hollow when that run didn't name it) and `failed in N of the last M runs` / `passed in all M kept runs`, the screenshots, trace/video/other files. The full error (deduplicated across widths, with Playwright's source snippet), stdout/stderr behind an expander. **Steps** (Playwright, a tab per width): `test.step` blocks with the actions and expects under them, each with its locator and what it typed, went to or expected, its time, and its line (a click lights it in the code). **Code**: the test's own block from its file at the commit the run checked (`lib/gate/source.ts`: from Playwright's line, or bun's `test("<title>"` line, to the bracket that closes it), lines a step ran on highlighted. Planted bugs it caught.
- **Planted bugs** (`lib/gate/probe/coverage.ts`): caught of planted, missed, excluded or stale, files probed, probes (replays), and a bar per probe's catch rate against `minRate` (a replay's bar dashed and labelled `replay`, its own rate on it, the list's file name in its tooltip; the headline's bar carries the bold value). Then, behind one expander, every stored probe's bugs per source file (misses first, then `probe.critical`, tagged), one row per distinct change (file + trimmed before + after; a `--from` replay adds to its history dots, hollow), newest outcome first-class: caught by which check and which test titles (widths folded), missed, excluded or stale with the reason; a miss from a probe other than the headline one says so; a newest outcome from a replay keeps the replay's result and a dashed `replay` tag.
- **Coverage maps** (each an expander, open when it has gaps), **Never probed** (source files at HEAD that could carry a bug and no probe ever planted a counted bug in, by folder, behind an expander), **Not run yet**.

**Test detail: `$GATE_ARTIFACTS` and gate's Playwright reporter** (`lib/gate/artifacts.ts`, `lib/gate/reporter/playwright.cjs`). What a log can't carry. Whenever a check gets `$GATE_COVERAGE` (a run, a probe's baseline; never a planted bug), it also gets `$GATE_ARTIFACTS` = `<work root>/runs/<run>/artifacts/<check>/` (emptied first) and `PW_TEST_REPORTER` = the reporter's absolute path, unless the repo passes its own `PW_TEST_REPORTER` through `pass[]`. Playwright appends that reporter to the repo's own (an undocumented env var its VS Code extension uses; checked against @playwright/test 1.65.1), so **a repo changes nothing** to get steps, errors and failure screenshots; `bun test` ignores it.
- The reporter (plain CommonJS, Node built-ins only: Playwright loads it from outside the repo) appends one line per attempt to `results.jsonl`: id, absolute file, line, column, project, title chain (` › `), retry, status, expected status, ms, start time, steps (categories `test.step`, `pw:api`, `expect`; hooks, fixtures and attaches left out; ≤ 400, each with title, locator, a short param (url, value, text, key, expected, name; a value typed into a field whose locator says password/secret/token/otp/pin is `•••`; a URL the locator already shows is dropped), depth, ms, first error line, its line when in the test's own file), errors (message and snippet, ≤ 16 kB), stdout/stderr (≤ 16 kB each), attachments. Images are copied into `<id>/` always; trace, video and other files only when the attempt failed. It never throws into the run.
- After the check gate re-encodes the PNGs as WebP (quality 80, ≤ 1280 px wide) when `ffmpeg` is on PATH, 4 at a time, and points `results.jsonl` at them; one that fails keeps its PNG.
- **End-state screenshots** of passing tests need the repo's config to take them: `screenshot: process.env.GATE === '1' ? 'on' : 'only-on-failure'`. Nothing can set that from outside.
- **Disk:** `results.jsonl` lives and is pruned with its run (newest 20). The files beside it only on the newest 3 runs that have any (`pruneArtifacts`, when a run ends). beep3 (150 flows × 2 widths), 2026-11-22: 0.7 MB a run with steps only; 15 MB with an end-state screenshot per test (300 WebP); 45 MB at most kept.
- `gate tests` reads it only for the page (`gatherDetails`, keyed by the reporter's file with the clean copy's root stripped, project and title, the same key as the log's); `gate tests --json` doesn't carry it. `testsReport(cwd, {recent: true})` adds each test's result per kept run (`history.recent`) and the kept runs (`kept`) for the page; `--json` keeps its shape.

**Coverage maps.** A repo's own "what covers what" grid, without gate knowing the repo. While a check runs under gate (`gate run`, a probe's baseline; never a planted bug's run), `$GATE_COVERAGE` is an empty folder kept with that run: `<work root>/runs/<run>/coverage/<check>/` (emptied first, pruned with the run). The check may write any number of `<name>.json` files there, one map each (`lib/gate/maps.ts`, zod, `.strict()`):
```json
{ "title": "Screens × widths", "columns": ["desktop", "phone"],
  "rows": [ { "item": "/settings", "group": "studio",
              "cells": { "desktop": true, "phone": false },
              "coveredBy": ["settings/senders · a sender shows as unverified"] } ] }
```
`title` ≤ 80, 1–24 `columns`, ≤ 5000 `rows`. A cell is `true` (covered), `false` (a gap), `null` or missing (doesn't apply), a string ≤ 40 shown as is, or `{ok, text?, by?: [titles]}`. `group` and `coveredBy` are optional; a row with any false cell is a gap. `gate tests` lists each map (rows × columns, gaps, check) or why a file isn't one; `--json` carries them as `maps: [{check, run, file, map?, gaps?, error?}]`, from the run each check's results come from; `--html` draws each as a grid and checks every `coveredBy` title against the last run (failing, or not in it). Unset outside gate: a check writes nothing then. beep3 is the first user (screens × widths from `web/e2e/coverage.ts`, tRPC procedures × callers from `web/server/router.access.md`).

**Windows.** Not built: `bin/gate.mjs` tells you to run gate from WSL and exits 2. Linux, macOS and WSL run it. `gate tests --html` opens the page in Windows' browser from WSL, else with `open` (macOS) or `xdg-open` (Linux).

## Accepted risks / open questions

- Only agents are checked, and only through agent-guard: a push that doesn't go through Bash `git push` (a script, `gh`, an alias, Sal's own terminal) isn't seen. Sal's call: agents are the only pushers.
- The guard reads the remote's state from remote-tracking refs, which are as fresh as the last fetch. A stale `origin/main` can hide a weakening (if the remote moved to block since) or report "nothing new" wrongly only when the local ref equals a stale tracking ref, which a push then wouldn't change anyway.
- `NO_COLOR=1` with `FORCE_COLOR=0` (both per the contract) makes Node print a warning in every Node process a check starts ("The 'NO_COLOR' env is ignored due to the 'FORCE_COLOR' env being set"). Harmless noise in logs; the counts parser ignores it.
- `git archive` leaves out submodules and honors `export-ignore`: a repo that relies on either gets an incomplete copy.
- Two repos with the same folder name (W:\code\x and G:\code\x) share a slug, so their template caches evict each other.
- Report-mode background runs append to `<work root>/push.log`, not a per-run log, because the run id doesn't exist yet when the guard starts it.
- The receipt is only as strong as the key file: anyone who can read `~/.gate/key` (or `~/.destedtui/gate/key` on a machine that ran gate before it moved here) can sign one. It stops agents forging by accident or by shortcut, not a determined local user.
- The probe plants bugs after `setup`: a check that runs a build artifact made by `setup` (rather than the source) won't see the bug, and the probe will call it missed.
- Bugs run one at a time; a repo with a 40 s flows check and 30 bugs takes the better part of half an hour. `--jobs` is a later pass.
- The test-file "idle" list depends on runners naming the file: Playwright always does; bun only for files it prints a `path:` header for. A file only ever reached through another (a shared helper) shows as idle.
- `PW_TEST_REPORTER` is undocumented Playwright (its VS Code extension uses it). If an upgrade drops it, the page loses steps and screenshots and says nothing else changed; the fix then is a gate-set variable the repo's config adds to its reporters.
- The page embeds every test's code and history: beep3's is ~3 MB. Fine for a local file; a repo with ten times the tests would want the data split out.
- A test's code is cut by a bracket scanner, not a parser: a regex literal holding an unbalanced bracket can end the block early or late (it still shows from the right line).
