Three file names, and nothing else counts as a test

*.rule.test.tsMay touch pure code only. It runs with no environment at all, so one that reaches for a database fails on import.
*.api.test.tsMay touch the real router and its own copy of Postgres. Never the dev database, never a real API key.
*.flow.spec.tsMay touch the app only the way a person does: the production build, through a browser, at two widths.

The name says what a test is allowed to depend on. A names check runs first and fails on anything else. No other unit tests get written, and an old one is deleted the first time it blocks a change you asked for.

Four rules keep a green run honest

A check has to have been seen failing once

Break the code on purpose and watch the check go red before trusting its green.Without it, half of 66 planted bugs passed every check.

The builder doesn't write its own pass mark

What a flow must show is written down before the code. A separate agent turns that line into the test.Without it, the agent that wrote the bug writes the test that agrees with it.

A skipped test is a failed test

No skip, no todo, no run that finds zero tests, no test that passes when a setting is missing.Without it, one repo had 88 of 438 test files skipping themselves.

Checks run on a clean copy, with their own database

Never the working folder and never the dev database. A file nobody committed isn't in the copy.Without it, 32 test files in one app were writing to the dev database.

Planted bugs put a number on green

A green run only means something if the checks can fail. So gate probe changes one line at a time, runs every check, and counts how many changes get caught.

The percentages are from the first existing app brought on: 174 procedures, 1,071 API tests and 164 flow runs, with a full gate run in two and a half minutes.

Green still doesn't mean no bugs

On code the tests weren't written against. The point is that the number is known and can be moved.

It can't judge taste

Whether a screen feels right is your call, and those flows stay on your list.

Some things no check reaches

A mobile build on a real device, a third-party dashboard, an email as it lands in an inbox.

Nothing is stopped

A red run is reported and the push still goes through. Blocking exists and stays off until you turn it on.
